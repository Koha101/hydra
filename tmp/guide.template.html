Hydra → Slack — Setup Guide

Slack only · no Discord needed
0 of 6 steps done · progress saved in this browser

Connect a Slack app to a Claude Code session. Two processes do the work: a daemon (holds the Slack connection, routes messages) and a bridge (an MCP plugin inside Claude). They talk over a unix socket — so always start the daemon first.

✅
Do you need Discord too? No. The daemon runs one platform per process. Discord would be a fully separate, parallel daemon with its own state dir — only if you also want the bot in Discord. For Slack, everything below is complete on its own.
1

Create the Slack app from the manifest

Go to api.slack.com/apps → Create New App → From an app manifest. Pick your workspace, then paste the JSON below.

👤
Create your own app — don't reuse a shared one. A Slack app is one event stream: if a second daemon connects to the same app, Slack splits messages across both connections and neither bot behaves predictably. This manifest uses the name BitBot so it won't collide with an existing Byte app. The name is cosmetic — Hydra references the bot by tokens, never by name.

app manifest (JSON)

{
  "display_information": {
    "name": "BitBot",
    "description": "Claude Code chat bridge",
    "background_color": "#2c2c2c"
  },
  "features": {
    "app_home": {
      "home_tab_enabled": false,
      "messages_tab_enabled": true,
      "messages_tab_read_only_enabled": false
    },
    "bot_user": {
      "display_name": "BitBot",
      "always_online": true
    }
  },
  "oauth_config": {
    "scopes": {
      "bot": [
        "app_mentions:read",
        "channels:history",
        "channels:read",
        "chat:write",
        "files:read",
        "files:write",
        "groups:history",
        "groups:read",
        "im:history",
        "im:read",
        "im:write",
        "mpim:history",
        "reactions:read",
        "reactions:write",
        "users:read"
      ]
    }
  },
  "settings": {
    "event_subscriptions": {
      "bot_events": [
        "app_mention",
        "message.channels",
        "message.groups",
        "message.im"
      ]
    },
    "interactivity": {
      "is_enabled": true
    },
    "org_deploy_enabled": false,
    "socket_mode_enabled": true,
    "token_rotation_enabled": false
  }
}
2

Grab the two tokens, then install the app

You need both tokens — one for the WebSocket, one for the API:

TokenWhere to get itFor
xapp-… Basic Information → App-Level Tokens → Generate
name socket-mode, scope connections:write		 Socket Mode connection
xoxb-… OAuth & Permissions → Bot User OAuth Token posting & reacting

Then Install App → Install to Workspace → Authorize. Org-restricted workspace? An admin may need to approve the scopes.

3

Write the config files

Create the state directory:

mkdir -p ~/.claude/channels/slack

~/.claude/channels/slack/.env — paste your two tokens:

.env

CHAT_PLATFORM=slack
SLACK_BOT_TOKEN=xoxb-...
SLACK_APP_TOKEN=xapp-...

~/.claude/channels/slack/access.json — who's allowed to DM the bot. Use your Slack user ID (Profile → ⋮ → Copy member ID; looks like U084P1E92NP):

access.json

{
  "dmPolicy": "allowlist",
  "allowFrom": ["UXXXXXXXX"],
  "groups": {},
  "pending": {}
}
4

Enable the bridge plugin in Claude

In ~/.claude/settings.json (the name says "discord" for historical reasons — it's platform-agnostic):

~/.claude/settings.json

{
  "enabledPlugins": {
    "discord@claude-plugins-official": true
  }
}
⚠️
If your claude.ai account has a native Slack connector (Settings → Connected Apps), disable it — otherwise Claude uses that instead of this bridge and the bot stays silent.

start-slack-byte.sh copies bridge.ts into the plugin cache for you — no manual copy needed.

5

Start the two processes — daemon first

1) The daemon. SPAWN_CWD is where spawned sub-sessions run (required). Opens tmux session discord-daemon:

terminal — step 5.1

cd ~/Documents/angellist/hydra

DISCORD_STATE_DIR=~/.claude/channels/slack \
CHAT_PLATFORM=slack \
SPAWN_CWD=~/angellist \
  ./start-daemon.sh

2) Claude + bridge — only after the daemon socket exists. Opens tmux session slack-byte:

terminal — step 5.2

export DAEMON_SOCK=~/.claude/channels/slack/daemon.sock
export CLAUDE_CONFIG_DIR=~/.claude
./start-slack-byte.sh

Watch it live: tmux attach -t slack-byte. The script greets a default DM (BYTE_CHANNEL) from working dir ~/angellist (BYTE_CWD) — override those env vars to change either.

6

Test it in Slack

DM BitBot in Slack (or @mention it in a channel you've added to groups). It should reply through Claude.

Type spawn: <task> in a DM to fork an isolated sub-session in its own thread — Slack threads route straight back to that sub-session.

Triage — if the bot stays silent
  • No reply at all → tmux attach -t slack-byte. Most common cause: the native claude.ai Slack connector is hijacking it (Step 4), or your user ID isn't in allowFrom.
  • socket not found from start-slack-byte.sh → the daemon isn't up. Run step 5.1 and confirm ~/.claude/channels/slack/daemon.sock exists.
  • Daemon exits immediately → SPAWN_CWD is required; set it.
  • Token errors → check the daemon log: tmux attach -t discord-daemon. Verify both tokens are in .env and the app is installed to the workspace.
